# `@platform/*` → `@atizar/*` scope rename — sub-project 7c-E

**Date:** 2026-06-13 · **Branch:** `feat/7c-packaging` · **Status:** design

## Goal

Rename the placeholder npm scope `@platform/*` to the final brand scope **`@atizar/*`** across the
whole monorepo. This fulfills the CLAUDE.md note *"`@platform/*` is a placeholder scope — rename
before any npm publish"* and aligns the package names with the already-present `ATIZAR_` env
namespace and the (user-authored) README/LICENSE.

The five packages become: `@atizar/core`, `@atizar/providers`, `@atizar/integrations`,
`@atizar/server`, `@atizar/react`.

## Non-goals (YAGNI)

- No npm publish, no version bumps, no registry config — the rename is the deliverable; publishing
  is launch-time logistics.
- No change to `exports` subpath KEYS (`./gmail/*`, `./db/schema`, `./styles.css`) — only the scope
  PREFIX of consumers' import specifiers changes.
- No change to the `ATIZAR_` ENV namespace (already final) or to any code behavior.
- No restructure of packages, no dependency changes beyond the `name`/workspace-dep strings.

## Decision (locked with the user, 2026-06-13)

**Rename EVERYWHERE, including the protected docs.** `@platform/core` appears in `ARCHITECTURE.md`
(invariant I5) and `PHILOSOPHY.md`. The user explicitly confirmed renaming these — it is a
**cosmetic scope-name swap; no invariant's meaning changes** (I5 still reads "userland imports only
the public SDK … never internals", just under the new name). This explicit confirmation satisfies
the `check-foundation` protected-doc rule; the `guard-foundation-edits` hook may still prompt on the
two doc edits — proceed (already authorized). Leaving docs at `@platform` while code says `@atizar`
would be a worse, inconsistent state.

## Inventory (from discovery, 2026-06-13)

- **5** package `name` fields: `packages/{core,providers,integrations,server,react}/package.json`.
- **`apps/inbox/package.json`**: 5 workspace deps (`"@platform/X": "*"`) + 4 `db:*` scripts that
  inline `import('@platform/server')`.
- **101** code files (`*.ts/tsx/mjs/js/json`) referencing `@platform/` (imports).
- Subpath import specifiers in use: `@platform/integrations/gmail/*` (auth, client, list-unread,
  get-email, get-latest-email, create-draft, modify, check-credentials) and
  `@platform/react/styles.css`. `@platform/server/db/schema` is defined in `exports` but NOT
  imported anywhere (drizzle.config uses a relative path).
- **NOT touched** (verified no `@platform` reference): `drizzle.config.ts`, all `tsconfig.json`,
  `vite.config.ts`, `vitest.config.ts`, `vitest.eval.config.ts` — they use relative paths / project
  references, not the scope name.
- **60** `.md` doc files reference `@platform`, including the two protected docs.

The token `@platform/` is unambiguous (no false positives), so the rename is a single global
string replace `@platform/` → `@atizar/` over all tracked files, plus a sweep for any bare
`@platform` (without slash) in prose.

## Execution

1. Global replace `@platform/` → `@atizar/` across all **git-tracked** files (code + docs).
2. Sweep for any residual bare `@platform` (e.g. "the @platform scope" in prose) → `@atizar`.
3. `yarn install --ignore-engines` — re-link the workspace symlinks under `node_modules/@atizar/*`
   (the no-build pattern resolves workspace deps by NAME via these symlinks; without reinstall,
   `@atizar/*` imports won't resolve).
4. `check-foundation` (boundary rename — expected CLEAR; the protected-doc edits are the
   pre-authorized cosmetic swap).

## Verification

`yarn typecheck && yarn lint && yarn test && yarn eval && yarn build` — all green. A grep confirms
**zero** remaining `@platform` occurrences in tracked files. (No browser E2E needed — a scope
rename changes no runtime behavior; the green build + test + eval is the proof. A quick `yarn dev`
boot smoke is optional confirmation that workspace resolution relinked.)

## Risks

- **Forgotten reinstall** → `Cannot find module '@atizar/...'` at boot/test. Mitigated by step 3 +
  the full verification gate.
- **A `@platform` in a place grep missed** (e.g. a lockfile-internal reference). `yarn.lock`
  workspace entries are regenerated by `yarn install`; the final zero-occurrence grep is the
  backstop.
